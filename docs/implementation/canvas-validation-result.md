# 原生Canvas计算与方法验证

新增 `tools/tests/canvas-layout.mjs`。测试直接转译当前 `MapLayout.ets` 与 `MindMapCanvas.ets` 实现；仅去除ArkUI装饰器和声明式build区，替换两个原生上下文构造器。真实fit、setZoom、selectAt、refreshDocument方法保持原样；ready=false时实际paint自行提前返回。此验证不执行Canvas绘图、不模拟手势系统，也不是手机帧率或性能验收。

## 覆盖

- 200/500节点、right/down布局：所有节点矩形两两不相交，图边界覆盖全部矩形；冻结输入后计算，不修改领域数据。
- 长中文节点逐行完整保留、节点高度容纳所有行；折叠后隐藏相应子树，childCount保留。
- emoji不能把UTF16高低代理项拆到不同绘制行。
- 320/360/390/480vp手机视口，每个尺寸分别检查200/500节点、平衡/星型、right/down实际fit后的所有矩形都在视口内。
- 实际selectAt在fit、平移、缩放后命中正确节点；空白位置不错误选中。
- 实际setZoom保持视口中心对应的图坐标不变，并发出当前显示百分比。
- 同一文档刷新保留平移缩放，切换文档重新fit。
- 最大合法500节点、每节点500中文字符的星型图紧凑视口边界。

首轮执行 `node --test tools/tests/canvas-layout.mjs`：15项全部通过。首次发现并报告主线程的两处边界均已修复并由实际源码复测：right布局高度约575k的合法长标签星型图在320×280视口需要zoom约0.00045，旧0.001最小值造成裁切；旧charAt逐UTF16码元会把emoji代理项拆到不同绘制行。主线程完成上述边界修复。

初次Node进程内四次布局计算耗时约0.28–1.96ms；此数字仅是本机Node纯布局调用用时，不包含ArkTS、设备、原生Canvas绘制、手势或字体，不作为手机FPS或运行性能结论。

## 主题与视口优化回归

布局刷新时建立ID索引，绘制父节点直接Map查找，平移重绘不重建布局或索引；色板按主题变化失效。重复尺寸通知不fit，实际尺寸变化保留当前图中心与缩放；首屏、换文档和手动fit仍适配。拖动和双指缩放取消时回退操作起点。

## 2026-11-23 2D / 3D 双视图

`MindMapCanvas` 新增 `viewMode` 与 yaw/pitch 旋转。2D 保持平面树；3D 使用透视相机：节点按 `(x, y, depth*70)` 旋转，投影前按 `1 + min(0.5, depth*0.15)` 展开树间距，透视比例为 `distance/(distance+z)`，默认 −20° / 20°。卡片保持正面朝向，绘制阴影、右下厚度和顶面，按相机深度从远到近排序，选中卡片补绘到最上层。连线、徽标、选中路径和命中测试使用投影后的坐标；3D 适应画布按当前角度的投影边界计算，切换视图自动复位并重排。单指旋转、双指平移、捏合缩放，pitch 限制 ±1 rad，复位按钮恢复默认角度。

回归增至 38 项并全部通过。新增 11 项覆盖：3D 投影随层级缩小、yaw/pitch 改变投影位置与透视比例、3D 在 200/500 节点、320/360/480vp 视口和三组角度下完整适应、3D 命中旋转后的卡片、3D 绘制阴影/厚度/强调路径、500 卡片 3D 绘制、单指旋转/俯仰限制/取消/复位、默认角度十节点卡片不重叠、2D↔3D 切换重排。现有 500 节点绘制测试仍验证每帧 500 次父节点 Map 查找；3D 排序为每帧 O(n log n)。本机 Node 记录型上下文下，500 卡片 3D 绘制方法约 1.0ms；这只是桌面方法调用耗时，不包含 ArkUI 原生绘制、字体、手势或手机刷新率，不能作为 FPS 结论。
