## 开发时怎样同步

已有本地改动先提交到自己的功能分支或备份，保持工作区干净，再同步：

```powershell
git fetch origin
git switch 自己的分支名
git merge origin/main
```

每人优先改自己的模块；公共入口、路由、模型和 service 改动由统筹协调。提交 PR 前运行 `node tools/check-integration.mjs`，再使用团队统一的 DevEco Studio 编译。该脚本检查路由唯一性、builder、相对导入、字面量跳转目标和颜色资源，不能证明业务闭环已完成。

### 三条必演流程

1. 新建空间：填写 → 预览 → 返回修改 → 确认 → 首页出现空间 → 地图进入同一空间 → 节点 → 练习 → 反馈保存 → 原节点查看记录。
2. 栈队列：输入 A/B/C → 预测 → 运行 → 栈取 C、队列取 A，剩余 B/A 与 B/C → 保存一条对比记录 → 主动加入复习 → 清单可见且无自动排期。
3. 时间调整：打开 `task_101` → 预览 15+30 → 取消无变化 → 再确认 → 首页/总览/时间轴一致 → 撤销恢复；选择冲突时间应被阻止。

排期 Mock 固定“今天”为 2026-10-18，这是演示样例日期。答辩时说明样例日期；接后端后统一使用实际业务日期。每条流程都补测正常返回、重复提交、失败重试和过期 ID。
